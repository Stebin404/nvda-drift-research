# NVDA Concept-Drift Research

Supplementary code for **"Concept Drift Detection and Retraining Triggers
for Financial Forecasting: An NVDA Case Study."**

The paper asks whether general-purpose concept-drift detectors (ADWIN,
Page-Hinkley, KSWIN) can detect regime changes in NVIDIA (and, as a
generality check, AMD and TSLA) stock data around externally verified
earnings disclosures, and whether drift-triggered retraining of a
LightGBM forecaster improves on fixed-interval or no-retraining
baselines. See the paper for the full methodology and discussion; this
README is only about reproducing the numbers.

## Setup

```bash
pip install -r requirements.txt
```

Dependency versions are pinned (see the comment at the top of
`requirements.txt`) to the exact environment the tables below were
generated and verified against. This is not a style preference: this
repo already documents one case (KSWIN's internal random sub-sampling,
`drift/kswin_detector.py`) where an unpinned dependency silently
changed every downstream detection number. Don't loosen the pins
without re-running the rebuild scripts and diffing the output against
the paper.

## Data

`data/*_ohlcv_frozen.csv` are frozen OHLCV snapshots for NVDA, AMD, and
TSLA. **Yahoo Finance retroactively revises historical adjusted-close
values**, so re-pulling the "same" date range on a different day can
silently change detector alarm counts and precision/recall (confirmed
empirically -- see the paper's Data Availability section). Every
script in this repo reads from the frozen CSVs via `data/loader.py`;
delete a frozen CSV only if you deliberately want a live re-pull for a
new experiment, not to "refresh" existing results.

`data/earnings_dates_FINAL[_amd|_tsla].csv` are the manually-verified
earnings-event anchors (Section III-B of the paper): SEC EDGAR 8-K
filings individually confirmed to report quarterly revenue, not
inferred from price action. `data/fetch_earnings_ground_truth.py`,
`data/classify_earnings_candidates.py`, and
`data/finalize_earnings_dates.py` are the full provenance pipeline that
produced them from the raw SEC EDGAR full-text search API.

`data/fold_manifest.csv` and `data/earnings_accession_manifest.csv`
(generated by `python data/generate_manifest.py`) make the exact
rolling-origin fold boundaries and the SEC accession number behind
every earnings-event anchor directly inspectable, rather than only
reproducible by running the pipeline.

## KSWIN seed

River's `KSWIN` performs internal random sub-sampling as part of its
test statistic and is non-deterministic with `seed=None`. Every KSWIN
instantiation in this repo is seeded (`DEFAULT_KSWIN_SEED = 42` in
`drift/kswin_detector.py`); this was a real bug in an earlier draft
(alarm timings, and therefore precision/recall, changed between runs
on identical frozen data) and is why every reported KSWIN result here
is reproducible run-to-run on the frozen dataset.

## Reproducibility notes from this revision pass

- This environment installed `river==0.22.0` (a prebuilt wheel; building
  `river` from source here required a Rust toolchain that was not
  available). Re-running the fold-based tournament under this pinned
  version reproduces the paper's qualitative pattern (ADWIN/Page-Hinkley
  silent everywhere; KSWIN strongest on raw `Volatility_20`) but not
  bit-identical precision/recall at every tolerance versus the numbers
  already in the paper's `main.tex` -- e.g. NVDA residual-stream
  precision at tolerance=30 comes out to 0.200 here versus 0.250 (1/4)
  as originally reported. This is exactly the version-sensitivity risk
  this README's pinning section warns about: the frozen *data* is
  unchanged, but a different `river` build produces a different exact
  alarm count from the same fixed seed. The paper's existing tables were
  left as originally reported rather than silently overwritten; the new
  multi-ticker, hyperparameter-sweep, and KSWIN warm-start experiments
  above were all generated fresh under the pinned `river==0.22.0` and
  are internally consistent with each other, but should not be
  numerically diffed row-for-row against the original Table I/II figures.
- `xgboost` is listed in `requirements.txt` (used by `app.py`) but is
  not imported by any script that reproduces a paper table.
